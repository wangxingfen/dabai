# 代码任务隔离（worktree）

复杂/重构/核心大改先在独立 git 工作树里做：不污染主工作区，改完审查无误再合并，
出问题直接丢弃，回滚成本趋近于零。

## 用途

大白在主工作区（D:\AI\dabai）直接改代码时，核心文件改动会触发整进程热重载、
主工作区会积累大量未提交改动，改坏了恢复麻烦。隔离工作树把每次大改动放到
独立目录 + 独立分支（codex/<任务名>），主工作区全程不动。

## 适用场景

- 重构、跨多文件的大改动、没把握的修改
- 涉及核心文件（agent.py / server.py / codex_runner.py / harness/*）的改动
- 想先做个实验性改动、可能丢弃的任务

## 工作流

1. `wt_create(name=任务名)` → 得到工作树路径；
2. 用 code_ops 工具在隔离区改和验证（**所有工具传 `root=工作树路径`**）：
   `code_read` → `code_edit`/`code_patch` → `code_verify` → `code_smoke`；
3. `wt_status` / `wt_diff` 审查改动面，确认没改多、没遗漏；
4. 确认无误 `wt_merge` 合并回主分支（自动移除工作树、删除已合并分支）；
   改坏了 `wt_discard(confirm=true)` 一键回原点。

## 工具

| 工具 | 作用 |
| --- | --- |
| `wt_create` | 创建隔离工作树（路径 + 分支 codex/<名>） |
| `wt_list` | 列出全部工作树与脏状态 |
| `wt_status` | 查看某个工作树的状态（分支、改动清单、统计） |
| `wt_diff` | 相对主分支的完整差异（含未提交改动和领先 commit） |
| `wt_run` | 在工作树里执行命令（测试/语法检查） |
| `wt_merge` | 合并回主分支（--no-ff），成功后清理工作树和分支 |
| `wt_discard` | 丢弃工作树与分支（破坏性，必须 confirm=true） |

## 边界与注意

- 工作树统一放在隔离区目录下，分支前缀 `codex/`；
- 隔离区目录默认 `D:\AI\dabai_worktrees\`（与项目同级，git 规定工作树不能建在主
  工作区内部）；可在 `settings.json -> agent.worktree_dir` 改成任意绝对路径
  （相对路径按 `D:\AI\` 解析），改完即时生效无需重启；
- 隔离区改动**不触发**大白核心热重载；合并回主分支后才由 hot_reload 接管生效；
- 合并前必须 `wt_status` 确认工作树干净（有未提交改动会拒绝合并，先提交再说）；
- 主工作区有未提交改动时合并可能冲突——git 会拒绝并保留现场，不会覆盖已有改动，
  冲突时按提示解决后手动完成合并；
- `wt_discard` 无回收站，丢弃前先 `wt_diff` 确认确实不要了；
- 不要对非 `codex/*` 分支的工作树执行合并/丢弃（工具会拒绝）。
