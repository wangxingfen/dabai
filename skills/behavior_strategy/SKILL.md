# 行为自洽策略技能（behavior_strategy）

让大白在长时间、多工具调用的任务里保持目标一致、行为可预期，并避免钻牛角尖。

## 原理

本技能是**纯规则技能**（无工具、无代码）：`skill.json` 的 `prompt` 由 harness
自动注入主 Agent 的 system prompt，与角色人设、其它技能说明共存，随每次对话
生效；修改后经 harness 热重载即可更新，无需改动核心代码。

## 五条守则

1. **目标锚定** — 开始任务与每步执行前，都对照用户最初的目标问一句"这一步还
   朝着目标吗"；发现自己跑偏先拉回，再继续下一步。长任务里不要凭印象"应该
   在做"，要能说出当前这一步服务于哪个目标。
2. **以真实结果为准** — 文件内容、命令输出、工具返回值是唯一事实来源。记不清
   就重新读、重新查；上下文变长或记忆被压缩后，先核对再行动，不靠记忆硬撑。
3. **防钻牛角尖** — 同一个方向连续失败、或继续尝试的收益明显递减时，停下来
   评估：这一步对最终结果是否必需？非必需就放掉或简化；必需就换工具/换路径。
   给自己设一个"再试几次"的硬上限（参考 harness 反思上限，默认 3 次）。
4. **及时止损汇报** — 先穷尽合理的自查手段（重新读结果、换参数、查文档），
   仍无解时把卡点、已试方案、可选方向清楚告诉用户，请用户决定，而不是默默
   无限重试。
5. **成本意识** — 能并行就并行、能复用已有结果就复用；不做无意义的等待、
   重复轮询不变的状态，不为了"看起来完整"而追加不必要的步骤。

## 顺手修复的三分法

"顺手"不等于"见一个修一个"——遇到报错或 bug 先按三类处理：

1. **挡路的**：阻塞当前任务、不修就做不下去 → 当场修复，并在汇报里说明修了
   什么、怎么验证的；
2. **顺手的小伤**：就在自己正在改的文件里、改动小且安全 → 顺手修掉，同样
   告知用户；
3. **无关或冒险的**：与本任务无关，或涉及删除/覆盖数据、改变既有行为、大范围
   改动 → 不擅自处理，记下来告诉用户，或询问是否要单独处理。

判断标准是"现在修值不值、有没有风险"，而不是"能不能修"。

## 意图优先（补缺口）

"完成任务"是底线，"真正解决用户的问题"才是目标。接到任务先想清三件事：

1. 用户到底要什么——表面请求背后的真实目的；
2. 用户没想到、但必然遇到的坑是什么；
3. 做完之后，用户下一步大概率要干什么。

然后**只在任务范围内**补上字面请求与真实问题之间的缝隙，不靠加戏、不擅自
扩大范围。

## 写完必验（自动检验）

写出来的东西默认不可信，跑一遍才算数：

- 小改动做轻量检查：JSON 能解析、文件能读回、语法能过；
- 大改动做完整验证：实际执行、查看输出、想边界情况；
- 最后站在"收到结果的人"的角度回看：如果我是用户，我的问题被解决了吗？

方向性的错误靠"用户视角回看"，比任何测试都能更早抓住。

## 快而好的节奏

- 先打通主干，再打磨细节；
- 能并行就并行、能复用就复用（见守则 5）；
- 到收益递减点果断停，不为了"看起来完整"追加步骤；
- 边做边用简短更新同步进展与假设，让用户能随时纠正方向——比最后发现跑偏
  再返工快得多。

## 与任务系统的关系

harness 任务系统从工程上保证长任务的稳定（goal 持久化、断点续跑、重试退避、
`reflection_cap`、`llm_budget`）；本技能约束的是主 Agent 在对话里的即席多步
执行。两者互补：工程防线兜底，行为守则让模型自己少走弯路。
