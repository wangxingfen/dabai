# 定时任务（scheduler）

大白的长任务自动化：按固定间隔自动执行某件事，无人值守也照跑，干完自动汇报。

## 用途

把「定期检查服务器是否健康」「每小时看一眼某个目录有没有新文件」「每天定时
整理一份报告」这类重复性任务登记成定时任务，大白会用子智能体在后台按时执行，
完成后沿「子智能体汇报」链路自动转述结果。

## 适用场景

- 用户说：定期/定时/每隔一段时间/每天/每小时/帮我盯着/到时候提醒/自动检查
- 需要周期性观察外部状态（端口、进程、文件、网页、接口）并汇报变化

## 工具

| 工具 | 作用 |
| --- | --- |
| `sched_add` | 创建定时任务（名字 + 自包含任务描述 + 间隔），创建即触发第一次 |
| `sched_list` | 查看全部任务：下次执行、执行次数、最近结果、启停状态 |
| `sched_run_now` | 立即触发一次（不等周期；执行中则忽略） |
| `sched_toggle` | 启用 / 暂停 |
| `sched_remove` | 删除（破坏性操作，必须 confirm=true） |

## 用法示例

```text
sched_add(
  name="服务器健康检查",
  task="用 system_check 检查 8000 端口是否 LISTENING、进程是否响应 HTTPS 请求，
        不健康时在汇报里明确指出问题与修复建议",
  interval="5分钟",
)
```

## 边界与注意

- 任务由**通用子智能体**执行（与 sub_agent_spawn 同一后台池），有工具、有轮次上限，
  单任务最长约 30 分钟，超时自动取消；
- interval 支持秒数或中文（30秒 / 5分钟 / 1小时 / 1天），最短 30 秒；
- 任务描述必须**自包含**（要查什么、用什么工具、结果怎么汇报、验收标准是什么），
  子智能体看不到本对话上下文；
- 同名任务会被拒绝，不要重复创建；
- 删除无回收站，删除前先 sched_list 确认 job_id；
- 调度器随服务启动/热重载自动运行，服务重启后任务仍保留（data/scheduled_tasks.json）。
